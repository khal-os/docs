This is the verified first-run path for a Field Delivery Engineer using the public `khal` CLI.

<Warning>
  Install the CLI through the official KHAL-owned installer. Do **not** install or document the FDE CLI through npm, GitHub Packages, or raw package registries.
</Warning>

## 0. Prerequisites

```bash
node --version    # Node.js 20+; Node.js 22 is common in CI
npm --version
bun --version     # generated repos use Bun
khaw --version    # KHAW agent/workstation harness
```

Private KHAL app repos live in KHAL Gitea. Use the repo URL and credentials from the internal Gitea UI or onboarding note when you install from a private source. GitHub authentication is only relevant for public docs and public exceptions.

## 1. Install `khal`

```bash
curl -fsSL https://install.khal.ai/app-kit -o khal-app-kit-installer.sh
sh khal-app-kit-installer.sh
khal --version
khal --help
```

Expected command families include:

```text
new, start, build, deploy, install, list, logs, link, pull,
login, git, whoami, logout, config, target, context, doctor, update
```

## 2. Log in to a target

On a workstation with a browser:

```bash
khal auth login --target dev
```

On SSH/headless/agent sessions, print the URL instead of trying to open a browser:

```bash
khal auth login --target dev --no-browser
```

Verify identity and recovery state without printing secrets:

```bash
khal auth status --target dev --json
khal whoami --target dev --json
khal context --target dev --text
```

## 3. Scaffold a new app, service, or workflow

```bash
khal new app my-first-app
cd my-first-app
```

Backend-only or workflow-first work follows the same shape:

```bash
khal new service my-first-service
khal new workflow my-first-workflow
```

Generated repos are git-native KHAL apps: **repo + branch + `khal-app.json`**. Do not publish generated app repos to npm.

## 4. Build and typecheck locally

```bash
bun install
bun run build
bun run typecheck
```

A clean scaffold should pass all three before you touch a shared target.

## 5. Dry-run install before mutation

From the generated repo root:

```bash
khal install . --target dev --dry-run --json
```

A clean scaffold reports a passing summary and zero blocking checks:

```json
{
  "summary": {
    "status": "pass",
    "message": "Dry-run preflight passed; no mutations were performed."
  }
}
```

For a hosted app repo, always pass an explicit branch:

```bash
khal install <private-khal-gitea-repo-url> --branch dev --target dev --scope shared --dry-run --json
```

## 6. Install only after dry-run passes

```bash
khal install . --target dev --scope shared
```

If the target denies the mutation, ask for the permission named by the CLI. The current install path usually requires marketplace/install permission for the target organization.

## 7. Useful proof commands

```bash
khal target list --json
khal context --target dev --text
khal doctor --target dev
khal logs <app-id> --target dev --tail 50
khal status <app-id> --target dev --json
khal open <app-id> --target dev --check --json
```

`status` and `open` may be hidden compatibility helpers in some releases. They are useful for proof, but the authoritative public ladder is `khal --help` plus the installed command output.

## Troubleshooting

### `khal --version` is stale

```bash
which khal
khal update --channel latest
curl -fsSL https://install.khal.ai/app-kit -o khal-app-kit-installer.sh
sh khal-app-kit-installer.sh
khal --version
```

### Private Gitea repo fetch fails

```bash
tea login list
tea whoami
git ls-remote <private-khal-gitea-repo-url>
```

For SSH remotes, register your SSH key in Gitea first and use the SSH clone URL. Do not print or commit tokens, credential-helper output, or private remote URLs in public docs/issues.
