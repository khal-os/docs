title: "Install your FDE toolchain"
description: "Install Git, Node, Bun, tea, KHAW, and the KHAL CLI with current canonical commands."
---

Install the tools in this order. The KHAL and KHAW commands are the product surface; npm packages and private repo checkouts are development internals unless a runbook explicitly says otherwise.

## 1. Base tools

```bash
git --version
node --version    # Node 20+; Node 22 is common in CI
npm --version
bun --version
python3 --version
```

If Bun is missing:

```bash
curl -fsSL https://bun.sh/install | bash
```

## 2. Gitea CLI (`tea`)

Private KHAL engineering uses Gitea. Install `tea` using your OS package path or the internal onboarding note, then verify:

```bash
tea login list
tea whoami
```

If `tea whoami` fails, you probably need email/Gitea access finished first.

## 3. KHAW CLI

KHAW is the agent/workstation harness. The current install script clones the private KHAW repo on the `dev` branch and symlinks `bin/khaw` into `~/.local/bin`.

```bash
git clone --branch dev https://git.namastex.io/khal-apps/khaw.git ~/.khaw-src
mkdir -p ~/.local/bin
ln -sf ~/.khaw-src/bin/khaw ~/.local/bin/khaw
export PATH="$HOME/.local/bin:$PATH"
khaw --version
khaw status
khaw doctor
```

If your shell cannot find `khaw`, add this to your shell profile:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

## 4. KHAL CLI (`khal`)

AppKit distribution is KHAL-owned. Do **not** install or document the FDE CLI through npm. Use the official installer:

```bash
curl -fsSL https://install.khal.ai/app-kit -o khal-app-kit-installer.sh
sh khal-app-kit-installer.sh
khal --version
khal --help
```

Known top-level verbs include:

```text
new, start, build, deploy, install, list, logs, link, pull,
login, git, whoami, logout, config, target, context, doctor, update
```

`build` and `list` may still be compatibility/stub surfaces depending on the release channel; `doctor`, `login`, `install`, `logs`, `link`, and `pull` are real FDE surfaces.

## 5. First health snapshot

```bash
khaw --version
khaw doctor
khal --version
khal doctor --target dev
khal context --target dev --text
```

Keep this output. It is the baseline your agent uses to tell whether you are blocked by local setup, identity, source control, or target access.
