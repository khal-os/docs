title: "Model and OpenRouter credentials"
description: "How FDEs request, install, and verify model-provider credentials without leaking secrets."
---

Agents need model access, but credentials are secrets. Docs should teach the request and verification shape, not publish keys.

## Request path

Ask your onboarding owner for one of these approved routes:

- shared KHAW/Hermes profile already configured for your workstation;
- a personal OpenRouter key with budget/usage policy;
- another approved provider credential for the model family your work requires.

Use this exact request:

```text
Please provision model access for my KHAL FDE KHAW profile.
Needed for: code review, docs, KHAW Purpose/Wish work, and pack development.
Please provide the approved provider route, budget limits, and whether I should configure a personal `.env` key or use an existing profile credential pool.
```

## Install without leaking

Never paste a key into public docs, screenshots, issues, or chat transcripts. Put secrets only where the configured runtime expects them.

For Hermes/KHAW sessions, the operator may configure:

```bash
hermes config env-path
hermes auth list
hermes model
```

If you are told to set OpenRouter locally, use the `.env` path reported by Hermes and verify without printing the value:

```bash
python3 - <<'PY'
import os
print('OPENROUTER_API_KEY set:', bool(os.getenv('OPENROUTER_API_KEY')))
PY
```

## Proof

Good proof:

```text
Provider route configured: openrouter
Model family approved: <name>
Budget policy: <brief>
Verification: agent completed a trivial model call; no key printed
```

Bad proof:

```text
OPENROUTER_API_KEY=sk-or-...
```
