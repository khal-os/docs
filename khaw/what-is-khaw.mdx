---
title: "What is KHAW?"
description: "KHAW is the additive Hermes distribution, FDE workstation harness, and agent-first governance layer for Khal OS work."
---

KHAW is how a KHAL FDE and their agent become operational without forking the upstream agent runtime. It packages installation, policy, doctor checks, profile templates, Purpose Sessions, Wish/Work registry views, and optional extension components around Hermes.

## What KHAW owns

- FDE onboarding and pre-email provisioning plans.
- KHAW CLI (`khaw`) status, doctor, update, FDE provision/verify/enroll flows.
- Hermes plugin surfaces such as `/khaw`, KHAW tools, Purpose Session registry, and future Wish/Brainstorm commands.
- Brain-canonical work artifacts under `brain/wishes/`.
- Agent-first context: what to paste to a KHAW/Hermes agent, what evidence to collect, and what to avoid.

## What KHAW does not own

- Customer production mutation without approval.
- Private repo secrets in public docs.
- Mintlify deployment credentials.
- Raw model-provider credentials.
- Replacing upstream Hermes core when a plugin/tool/hook can do the job.

## First commands

```bash
khaw --version
khaw status
khaw doctor
khaw fde verify --json
```

## Hermes plugin proof

Inside a KHAW-enabled Hermes session, use:

```text
/khaw status
```

The plugin also exposes read-only tools for KHAW status, Purpose Sessions, and active Work Registry. Those tools are for evidence and context; they should not mutate customer systems.
