---
title: 'khal-app.json schema'
description: 'The complete manifest reference, derived from @khal-os/types and aligned with git-native pack installs.'
---

Every pack ships a `khal-app.json` at its root. The schema lives in [`@khal-os/types`](https://github.com/khal-os/app-kit/tree/main/packages/types) — this page is a field-by-field reference.

The `@khal-os/app-kit` package ships the `khal` CLI; `khal dev manifest` validates and inspects your manifest. Invalid manifests fail CI before they ship, and pack-install policy checks also reject npm-publish metadata in pack/app repos.

<Warning>
The schema currently keeps a legacy `frontend` object for backward compatibility, but the pack-install policy rejects package identity for new git-native pack/app repos. New manifests should use `bundlePath` or the current install-pipeline field instead of package identity.
</Warning>

## Top-level fields

<ParamField path="kind" type="'app' | 'service' | 'workflow'" required>
Discriminator for the manifest kind. Use `app` for user-facing packs.
</ParamField>

<ParamField path="id" type="string" required>
Unique pack identifier. Must match the package directory name. Lowercase, dash-separated.
</ParamField>

<ParamField path="name" type="string" required>
Human-readable pack name shown in the desktop launcher.
</ParamField>

<ParamField path="version" type="string" required>
Semantic version. Normally kept in sync with the pack's release tag and local build metadata.
</ParamField>

<ParamField path="description" type="string" required>
Short description for the marketplace listing.
</ParamField>

<ParamField path="author" type="string" required>
Author name or organization.
</ParamField>

<ParamField path="icon" type="string" required>
Path to the pack icon, relative to the pack root.
</ParamField>

<ParamField path="permissions" type="string[]" required>
Permission strings the pack requires. Examples: `"nats:publish"`, `"nats:subscribe"`, `"user:read"`. Permissions are checked by the platform before the frontend loads and before services are started.
</ParamField>

<ParamField path="bundlePath" type="string">
Relative path to the pre-built ESM bundle within the pack repo, for example `package/dist/index.mjs`. Use this for git-native frontend loading when the install pipeline expects a built bundle path.
</ParamField>

<ParamField path="backend" type="object">
Backend configuration. Omit entirely for frontend-only packs.

<Expandable title="backend fields">
  <ParamField path="backend.image" type="string">
  Container image name (without tag) for your service — e.g., `ghcr.io/khal-os/pack-terminal-service`.
  </ParamField>
  <ParamField path="backend.helmChart" type="string">
  OCI URL of your packaged Helm sub-chart — e.g., `oci://ghcr.io/khal-os/charts/pack-terminal`.
  </ParamField>
  <ParamField path="backend.env" type="object">
  Static env variables your service receives. Avoid customer-specific values; declare configurable values in `env[]` instead.
  </ParamField>
  <ParamField path="backend.ports" type="number[]">
  Ports your service binds internally. The platform assigns proxy ports at runtime.
  </ParamField>
</Expandable>
</ParamField>

<ParamField path="env" type="array">
Environment variables customers configure per install. See [Customer install](/release/customer-install) for the customer-side flow.

<Expandable title="env entry shape">
  <ParamField path="key" type="string" required>
  Variable name (e.g., `MY_API_KEY`).
  </ParamField>
  <ParamField path="description" type="string" required>
  Human-readable description shown in the admin's config UI.
  </ParamField>
  <ParamField path="required" type="boolean" required>
  Whether the pack refuses to run without this variable set.
  </ParamField>
  <ParamField path="default" type="string">
  Default value if not configured.
  </ParamField>
  <ParamField path="type" type="'string' | 'number' | 'boolean' | 'secret' | 'url'">
  Affects validation and UI rendering. `secret` values never appear in the frontend or in logs.
  </ParamField>
</Expandable>
</ParamField>

<ParamField path="views" type="array">
Optional. If your pack exposes multiple windows or view modes, declare them here with per-view permission and role requirements.
</ParamField>

<ParamField path="services" type="array">
Alternative to `backend` for multi-service packs. Each entry declares a named service with optional `command`, `entry`, `runtime`, `health`, `restart`, and `ports`. See [Backend overview](/services/backend-overview).
</ParamField>

<ParamField path="apps" type="array">
Optional bundle-pack entries for multiple frontend apps in one repo. Follow the current bundle install contract and avoid npm package identity fields in new manifests.
</ParamField>

<ParamField path="sandbox" type="object">
Advanced. Provision a per-user container when the pack is installed. Used for high-isolation packs. See the `app-kit/packages/types` source for full field shape.
</ParamField>

<ParamField path="defaultScope" type="'shared' | 'user'">
Default scope when an installer doesn't specify one. Defaults to `shared` if omitted.
</ParamField>

<ParamField path="allowedScopes" type="Array<'shared' | 'user'>">
Scopes this pack supports. Defaults to both `shared` and `user` if omitted.
</ParamField>

## Complete example

```json khal-app.json
{
  "$schema": "https://raw.githubusercontent.com/khal-os/app-kit/dev/packages/types/src/khal-app-schema.json",
  "kind": "app",
  "id": "my-pack",
  "name": "My Pack",
  "version": "1.0.0",
  "icon": "./package/src/assets/icon.svg",
  "description": "What my pack does in one line",
  "author": "My Company",
  "defaultScope": "user",
  "allowedScopes": ["user", "shared"],
  "permissions": ["nats:publish", "nats:subscribe", "user:read"],
  "bundlePath": "package/dist/index.mjs",
  "backend": {
    "image": "ghcr.io/khal-os/pack-my-pack-service",
    "helmChart": "oci://ghcr.io/khal-os/charts/pack-my-pack",
    "env": {
      "KHAL_PTY_SHELL": "/bin/bash"
    },
    "ports": [8080]
  },
  "env": [
    {
      "key": "MY_API_KEY",
      "description": "API key for the external service",
      "required": true,
      "type": "secret"
    }
  ]
}
```

<Note>
For fields this page does not enumerate, consult `app-kit/packages/types/src/manifest.ts` directly. The Zod schema there is the canonical source. As of this cleanup, product/schema still contains compatibility fields that conflict with the stricter git-native policy; the policy checker is the source of truth for new pack/app repos.
</Note>
