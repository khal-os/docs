This is the first page for a newly hired Forward Deployed Engineer. Assume you have **only an enrollment code** and no company email yet. Your job is to turn that code into a safe working loop: identity, email or pending-email proof, workstation/LXC access, KHAW, KHAL CLI, source access, model access, and one small proof that does not touch customers or production.

## Mental model before your first ticket

- **Khal OS** is the product/runtime surface where packs, services, settings, terminal views, and customer environments live.
- **KHAW** is the FDE workstation and agent harness around Hermes: install/doctor/update, Purpose Sessions, slash commands, context, evidence, and safe gates.
- **Khortex + Brain** are the context/reasoning surfaces. Use them before architecture changes and whenever you do not know the current truth.
- **KHAL CLI (`khal`)** is the app/deploy/source companion. Use `khal login`, `khal context`, `khal doctor`, `khal install --dry-run`, and `khal deploy --dry-run` before mutation.
- **Private source** usually lives in KHAL Gitea. Public docs live in GitHub/Mintlify. Do not confuse the two.

## First proof target

Run this only after enrollment/access/toolchain pages say you are ready:

```bash
khaw --version
khaw status
khaw doctor
khal --version
khal context --target dev --text
khal whoami --target dev --json
khal new app hello-fde
cd hello-fde
bun install
bun run build
bun run typecheck
khal install . --target dev --dry-run --json
```

Simulated successful shape:

```text
$ khaw --version
KHAW version: 1.0.x
KHAW build status: ok

$ khal context --target dev --text
KHAL target: dev
Auth: signed in as <fde-email>
Reachability: ok
Mutation: none

$ khal install . --target dev --dry-run --json
{
  "summary": { "status": "pass", "message": "Dry-run preflight passed; no mutations were performed." }
}
```

If any step fails, keep the exact sanitized output and give it to your KHAW agent.
