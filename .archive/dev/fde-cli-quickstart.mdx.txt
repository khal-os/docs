This is the verified first-run path for a Forward Deployed Engineer using the public `khal` CLI.

<Warning>
  Install the CLI through the official KHAL-owned installer. Do **not** install or document the FDE CLI through npm, GitHub Packages, or raw package registries.
</Warning>

## 0. Prerequisites

```bash
node --version
npm --version
bun --version
khaw --version
```

Private KHAL app repos live in KHAL Gitea. Use the repo URL and credentials from the internal Gitea UI or onboarding note when you install from a private source.

## 1. Install `khal`

```bash
curl -fsSL https://install.khal.ai/app-kit -o khal-app-kit-installer.sh
sh khal-app-kit-installer.sh
khal --version
khal --help
```

Current top-level command families include:

```text
new, start, build, deploy, install, list, logs, link, pull,
login, git, promote, auth, whoami, logout, config, target,
context, doctor, dev, infra, telemetry, update
```

## 2. Log in to a target

Desktop/browser workstation:

```bash
khal login --target dev
```

SSH/headless/agent session:

```bash
khal login --target dev --no-browser
```

Verify identity and target without printing secrets:

```bash
khal whoami --target dev --json
khal context --target dev --text
khal git status --target dev
```

`khal auth login` and `khal auth status` are valid aliases, but the top-level `khal login` / `khal whoami` path is easiest for new FDEs.

## 3. Scaffold a new app, service, or workflow

```bash
khal new app my-first-app
cd my-first-app
```

Backend-only or workflow-first work follows the same shape:

```bash
khal new service my-first-service
khal new workflow my-first-workflow
```

Generated repos are git-native KHAL apps: **repo + branch + `khal-app.json`**. Do not publish generated app repos to npm.

## 4. Build and typecheck locally

```bash
bun install
bun run build
bun run typecheck
```

A clean scaffold should pass before you touch a shared target.

## 5. Dry-run install before mutation

```bash
khal install . --target dev --dry-run --json
```

Clean shape:

```json
{
  "summary": {
    "status": "pass",
    "message": "Dry-run preflight passed; no mutations were performed."
  }
}
```

For hosted private source:

```bash
khal install <private-khal-gitea-repo-url> --branch dev --target dev --scope shared --dry-run --json
```

## 6. Mutate only after dry-run passes

```bash
khal install . --target dev --scope shared
```

If the target denies mutation, ask for the permission named by the CLI. Do not bypass through raw Kubernetes, Helm, or manual secrets.

## Useful proof commands

```bash
khal context --target dev --text
khal doctor --target dev
khal logs <app-id> --target dev --tail 50
khal status <app-id> --target dev --json
khal open <app-id> --target dev --check --json
```
